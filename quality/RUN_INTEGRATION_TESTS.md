## Working Directory and Safety

Run from the repository root. Do not modify or delete source, database rows, Stripe objects, provider tasks, or storage objects unless the test environment is explicitly disposable. Store results only below `quality/results/`. Never interpret missing live credentials as a pass.

## Pre-Flight

- [ ] `pnpm install` state is present and `pnpm typecheck`, `pnpm lint`, and `pnpm test` pass.
- [ ] A disposable PostgreSQL database and test users (guest, user A, user B, admin) are available.
- [ ] `BETTER_AUTH_SECRET`, `NEXT_PUBLIC_APP_URL`, callback HMAC, Stripe test-mode, QStash test, provider sandbox, and R2 test-bucket variables are present.
- [ ] Webhook endpoints are externally reachable or a signed local tunnel is configured.
- [ ] Provider and Stripe tests have spending ceilings approved by a human.
- [ ] Record a shared UTC timestamp and unique test prefix.

## Test Matrix

| # | Check | Method | Pass criteria |
|---:|---|---|---|
| 1 | Guest API matrix | Call protected credit/video/upload/generate/admin endpoints | 401 for user routes; admin route denies; zero persistent/vendor state |
| 2 | Two-user isolation | User B references user A video/image/reservation | No data disclosure or mutation |
| 3 | Text generation happy path | Active sandbox model with user A | freeze → bound task → stored video → one settlement → COMPLETED |
| 4 | Image generation happy path | Owned reserved upload | validated input and same terminal invariants as #3 |
| 5 | Unsupported direct API options | Bypass UI with schema-valid unsupported capability | 400 before hold/provider call |
| 6 | Callback binding | Valid callback, then wrong provider/task/replay | first completes once; tampered requests mutate nothing |
| 7 | Slow/lost callback | Provider fixture remains processing beyond ten polls | durable requeue/timeout/escalation and resolved final hold |
| 8 | Completion storage failure | Inject R2/download failure | video returns retryable state; credits remain frozen, not settled/lost |
| 9 | Provider fallback | Fail primary and succeed eligible fallback | selected provider/task persisted and callback/poll contract remains valid |
| 10 | Stripe duplicate delivery | Replay same signed test event concurrently | one entitlement and one economic balance delta |
| 11 | Stripe return routes | Open success/cancel/portal destinations from generated sessions | each route returns a real localized account page, not 404 |
| 12 | Upload content boundaries | wrong owner/key/type/size/magic bytes | rejection before generation; reservation state consistent |
| 13 | Remote-media boundaries | redirect/private/DNS-change/oversize fixtures | no private connection; redirect/time/byte limits enforced |
| 14 | Admin role revocation | revoke database flag after session creation | next admin request returns 403 |

## Provider Matrix

Execute at most one live request per provider concurrently. For each enabled provider (`evolink`, `kie`, `apimart`, `bailian`, `zhipu`), record configured models, supported mode, callback capability, polling capability, task ID binding, terminal status mapping, and cleanup result. Skip only providers explicitly disabled in production configuration, and record the reason.

## Automated Commands

```powershell

pnpm test
pnpm typecheck

$env:SKIP_ENV_VALIDATION='1'; pnpm build
```

Pre-flight discovery must find at least one test before execution:

```powershell
pnpm exec vitest list quality/test_functional.test.ts
pnpm exec vitest list quality/test_regression.test.ts
```

The local group is `local-contract-and-regression` and covers `UC-001` and `UC-007`. The environment-gated group is `live-provider-payment-storage` and covers `UC-002` through `UC-006`; it is `skipped`, never `pass`, when the disposable database, sandbox credentials, spending approval, or cleanup authority is absent.

Database/provider/Stripe harness commands must be added by Phase 3 after confirming the available disposable environment. Do not invent credentials or issue live paid requests without approval.

## Post-Run Verification

1. Process: commands exit cleanly and logs contain terminal results.
2. State: every test video and hold is terminal/resolved or explicitly cleaned up.
3. Data: stored video URLs, provider bindings, Stripe orders, packages, holds, and transactions agree.
4. Content: downloaded output is nonempty, expected media type, and owned by the test user.
5. Quality: functional, unit, type, lint, build, and mechanical checks pass.
6. UI: generator, login, creations, credits/settings, and admin show the corresponding state.
