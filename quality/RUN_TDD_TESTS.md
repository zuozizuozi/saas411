# TDD Verification Protocol: VideoFly
> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-08-04 · Project: VideoFly

## Entry Gate

Run only after Phases 3–4 create `quality/BUGS.md`, regression-test patches, fix patches, and spec bases. Product source remains unchanged until an individual red result proves the regression test detects the bug.

## Per-Bug Red/Green Cycle

1. Read BUG ID, REQ, UC, spec citation, and behavioral contract.
2. Apply only `quality/patches/BUG-NNN-regression-test.patch` to a disposable/controlled worktree or copy.
3. Red: run the smallest Vitest test; it must fail for the stated behavior. Record JUnit XML when the installed reporter supports it.
4. Validate `BUG-NNN-fix.patch` with apply-check and TypeScript compilation.
5. Green: apply the fix and rerun the identical test; it must pass.
6. Run related tests, then the full suite, type check, lint, production build, and mechanical verification.
7. Revert the disposable test setup or commit only when separately authorized.

Tests must cite REQ, BUG, and a ≤15-word behavioral contract from the authoritative spec. Tests assert outcomes: route resolution, ledger delta, state transition, denial, byte bound, or provider parity—not internal call counts alone.

## Commands

```powershell
pnpm vitest run path/to/regression.test.ts --reporter=default
pnpm test
pnpm typecheck
pnpm lint
$env:SKIP_ENV_VALIDATION='1'; pnpm build
```

If JUnit reporting is unavailable without adding a dependency, set `junit_available` false; do not fail the TDD run solely for that reason.

## Structured Results

Write `quality/results/tdd-results.json` with exactly these top-level keys: `schema_version`, `skill_version`, `date`, `project`, `bugs`, `summary`. Each bug includes `id`, `requirement`, `red_phase`, `green_phase`, `verdict`, `regression_patch`, `fix_patch`, `fix_patch_present`, `patch_gate_passed`, `writeup_path`, `junit_red`, `junit_green`, `junit_available`, and `notes`.

Allowed verdicts: `TDD verified`, `red failed`, `green failed`, `confirmed open`, `deferred`. Summary contains exactly `total`, `verified`, `confirmed_open`, `red_failed`, and `green_failed`.

## Traceability and Writeups

Write `quality/TDD_TRACEABILITY.md` mapping Bug ID, Requirement ID, Spec Doc, Spec Section, Behavioral Contract, Test File:Function, Red Result, and Green Result. For every confirmed bug write `quality/writeups/BUG-NNN.md` with Summary, Spec reference, The code, Observable consequence, optional Depth judgment, The fix (mandatory inline unified diff), The test, and related issues when applicable.

## Outcomes

- Red test passes on unpatched code: rewrite it; verdict `red failed` until it truly detects the behavior.
- Red fails and green passes: `TDD verified`.
- Red fails but no fix exists: `confirmed open`, green `skipped`, with actionable inline diff.
- Environment prevents execution: `deferred` with precise prerequisite; red is never silently skipped.
- Green still fails: `green failed`; repair test/fix before closure.
