## Authentication and Authorization

- CT-001 [METHOD] `requireAuth()` returns the session user or throws HTTP 401 (`src/lib/api/auth.ts:25`).
- CT-002 [INVARIANT] Sensitive APIs derive the principal from request headers, never a client user ID (`src/lib/api/auth.ts:10`).
- CT-003 [METHOD] `requireAdmin()` requires authentication and current database role (`src/lib/api/auth.ts:36`).
- CT-004 [LIFECYCLE] Admin grants/revocations take effect without waiting for cookie-cache expiry (`src/lib/auth/admin-role.ts:12`).
- CT-005 [INVARIANT] Video read/mutation operations are scoped by authenticated user ownership.
- CT-006 [INVARIANT] Generation accepts only uploaded image URLs owned by the authenticated user (`src/app/api/v1/video/generate/route.ts:32`).

## Credit and Video Lifecycle

- CT-013 [ORDER] Credits are frozen before provider submission.
- CT-014 [INVARIANT] FIFO allocation consumes only active, unexpired, available packages.
- CT-015 [THREAD] Ledger mutations for one user are serialized with a database advisory lock.
- CT-016 [COMPAT] Repeated freeze/settle/release calls are idempotent for the same video hold.
- CT-017 [LIFECYCLE] Provider submission failure releases the hold and marks the video FAILED (`src/services/video.ts:341`).
- CT-018 [ORDER] Successful media storage precedes credit settlement (`src/services/video.ts:546`).
- CT-019 [ORDER] Credit settlement precedes marking a video COMPLETED (`src/services/video.ts:555`).
- CT-020 [LIFECYCLE] Completion failure returns UPLOADING to GENERATING while credits remain frozen (`src/services/video.ts:577`).
- CT-021 [INVARIANT] Every accepted paid generation ultimately reaches COMPLETED or FAILED and resolves its hold.

## Provider Routing and Callback

- CT-022 [CONFIG] `ProviderType`, provider configuration, API-key lookup, and factory represent the supported provider domain.
- CT-023 [ERROR] An unconfigured provider API key fails explicitly (`src/ai/provider-config.ts:54`).
- CT-024 [ORDER] Routing attempts eligible providers in priority order and records the selected provider/task binding.
- CT-025 [INVARIANT] Callback ingress accepts every callback-capable provider and rejects unknown provider identifiers.

- CT-027 [INVARIANT] Callback provider and external task ID must match the stored video (`src/services/video.ts:379`).
- CT-028 [LIFECYCLE] Missed callbacks are handled by durable reconciliation (`src/services/video.ts:324`).
- CT-029 [LIFECYCLE] Reconciliation exhaustion must requeue, terminate, or escalate without silently abandoning the hold.
- CT-030 [SECURITY] Callback payload parsing has an explicit request byte ceiling.
