# Code Review Protocol: VideoFly
> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-08-04 · Project: VideoFly

## Scope and Rules

Review authentication/authorization, video/provider/callback/storage, credits, Stripe, upload ingestion, and frontend/API contracts. Do not propose style or experience optimization. Every finding needs severity, exact file:line, observable consequence, requirement ID, and BUG/QUESTION/OK classification. Read bodies, grep before claiming absence, and keep unverified concerns as QUESTION.

Twelve baseline requirements span six core areas, with supplemental REQ-013 and REQ-014 added during reconciliation. Pass 2 must expand individual conditions rather than treating one REQ as one check.

## Pass 1 — Structural Correctness

Independently inspect:

1. Input validation: Zod boundaries, webhook bodies, URL parsers, enum prefix/suffix rejection, upload metadata.
2. Resource lifecycle: credit holds, upload reservations, provider tasks, storage downloads, timeout/abort behavior, error cleanup.
3. Concurrency/state: FIFO locks, idempotency claims, PENDING/GENERATING/UPLOADING/COMPLETED/FAILED transitions, callback/poll races.
4. Units/encoding: seconds, byte ceilings, Stripe amounts, credit multipliers, UTC timestamps, URL encoding.
5. Enumeration/whitelists: extract provider values mechanically; use `quality/mechanical/` evidence and cite each representation independently.
6. Security boundaries: session principal, object ownership, admin role, webhook signatures, SSRF, secrets, error disclosure.

Output `quality/code_reviews/pass-1-structural.md` with BUG, QUESTION, and verified-safe sections.

## Pass 2 — Requirement-by-Requirement Review

Read `REQUIREMENTS.md`. Evaluate every numbered condition in REQ-001 through REQ-014 separately; REQ-013 and REQ-014 are mandatory reconciliation follow-ups. Record SATISFIED, VIOLATED, or NOT PROVEN with citations. Explicitly test the candidate claims from Phase 1, but do not inherit their conclusions.

Mandatory probes:

- Build a protected-route inventory and check `requireAuth`/`requireAdmin`/ownership at every handler.
- Trace two-user identifiers through video, asset, upload, and billing operations.
- Compare generator catalog values with route schema, server validator, credit calculator, and provider eligibility.
- Trace freeze → provider bind → callback/poll → storage → settle/release for every exception and duplicate-delivery point.
- Compare the production route manifest with all Stripe success/cancel/portal destinations.
- Compare provider defined/handled lists using the mechanical receipts.
- Compare request limits across Stripe and AI callbacks.
- Verify the actual network connection is protected from DNS rebinding, not only the preflight lookup.

Output `quality/code_reviews/pass-2-requirements.md`.

## Pass 3 — Candidate and Regression-Test Design

For each VIOLATED item:

1. Reproduce the smallest observable behavior.
2. Assign `BUG-NNN` only after reproduction or decisive executable evidence.
3. Write a regression test patch under `quality/patches/BUG-NNN-regression-test.patch`; do not modify product source.
4. If environment-dependent, provide a deterministic seam or mark NOT PROVEN with the exact missing prerequisite.
5. Map the bug to REQ/UC/spec basis and propose the minimal fix surface.

Pay special attention to CAND-001 through CAND-007 and classify CAND-008 as a coverage gap unless it reveals a product defect.

Output `quality/code_reviews/pass-3-confirmation.md` and a combined summary at `quality/code_reviews/summary.md`.

## Completion Gate

- All 14 REQs and every condition reviewed, including reconciliation additions.
- All provider list claims supported by mechanical extraction.
- No missing-function claim without repository search evidence.
- Every BUG has a reproducer and regression-test patch; questions remain unnumbered.
- No product source file changed during review.
