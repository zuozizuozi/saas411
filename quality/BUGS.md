### BUG-007: DNS safety check is not bound to the media connection

- Primary requirement: REQ-010
- Spec basis: `quality/REQUIREMENTS.md:151-162`
- Use case: UC-004, UC-005
- Source: Spec Audit
- Severity: HIGH
- Evidence: `src/lib/storage.ts:72-79` resolves and validates addresses; `src/lib/storage.ts:104-109` later calls `fetch(currentUrl)` by hostname with no pinned dispatcher/custom lookup.
- Expected: the actual connection uses an address that passed public-network validation on every redirect.
- Actual: validation and connection perform separate DNS resolution operations.
- Observable consequence: a provider-controlled rebinding hostname can make the server connect to a private/link-local address after validation and upload the response to R2.
- Regression test: `test_bug_007_media_fetch_binds_validated_dns_address`
- Regression patch: `quality/patches/BUG-007-regression-test.patch`
- Fix: implemented directly in `src/lib/storage.ts`; the connection uses a validated IP while preserving Host/SNI, proxy tunneling, redirect revalidation, byte limits, and dispatcher cleanup.
- Closure status: **RESOLVED**. Public DNS answers are pinned into the actual Undici connection on every hop; non-public IPv4/IPv6 ranges and credential-bearing URLs are rejected.
