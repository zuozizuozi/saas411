# BUG-010: My Creations filters do not affect the requested result set
> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-08-05 · Project: VideoFly

## Summary

`useVideos()` includes filter state in its cache key but omits status, model, and sort from the request, so visible My Creations controls return the same unfiltered newest-first result.

## Spec reference

- Requirement: REQ-013
- Spec basis: `quality/REQUIREMENTS.md:178-187`
- Behavioral contract quote: "Changing a rendered status, model, or sort control changes the list query"

## The code

`src/components/creation/my-creations-page.tsx:29-48` passes filter state to `useVideos()`. At `src/hooks/use-videos.ts:30-37`, only limit and cursor reach `apiClient.getVideos()`. The client at `src/lib/api/dashboard-client.ts:49-56` lacks model/sort parameters, and `src/services/video.ts:871-876` always sorts descending.

## Observable consequence

Selecting a different status, model, oldest/newest order triggers a new query cache entry but returns the same list, making the controls functionally inert during normal account use.

## Depth judgment

The cache key changes and the UI rerenders, which can look connected during a shallow review; the values disappear at the request construction boundary.

## The fix

Carry the three filters through the hook, typed client, route, and service, validate status, and map UI model IDs to stored canonical IDs.

```diff
 return apiClient.getVideos({
   limit: 20,
   cursor: pageParam,
+  status: filter?.status === "all" ? undefined : filter?.status,
+  model: filter?.model === "all" ? undefined : filter?.model,
+  sortBy: filter?.sortBy,
 });
@@
+if (params.model) searchParams.set("model", params.model);
+if (params.sortBy) searchParams.set("sortBy", params.sortBy);
@@
-      .orderBy(desc(videos.createdAt))
+      .orderBy(options?.sortBy === "oldest" ? asc(videos.createdAt) : desc(videos.createdAt))
```
