# BUG-004: AI callback parses unbounded JSON
> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-08-04 · Project: VideoFly

## Summary

The provider callback calls `request.json()` at `src/app/api/v1/video/callback/[provider]/route.ts:40` without an application byte ceiling, unlike the Stripe webhook's 1 MiB bounded reader.

## Spec reference

- Requirement: REQ-006
- Spec basis: `quality/REQUIREMENTS.md:78-89`
- Behavioral contract quote: "Callback JSON is rejected before unbounded memory consumption."

REQ-006/REQ-010 require external payloads to be bounded before parsing. Contract: “callback JSON is rejected before unbounded memory consumption.”

## The code

Signature checks happen first, but a valid/leaked signed URL can still submit an arbitrarily large JSON body.

## Observable consequence

A compromised provider or leaked callback URL can consume avoidable memory and CPU in a serverless function before task validation.

## The fix

Reuse the bounded request reader and preserve `ApiError` status handling.

```diff
+const MAX_AI_CALLBACK_BYTES = 1024 * 1024;
@@
-    const payload = await request.json();
+    const payloadText = await readRequestTextWithLimit(request, MAX_AI_CALLBACK_BYTES);
+    const payload = JSON.parse(payloadText);
@@
-    return apiError("Callback processing failed", 500);
+    return handleApiError(error);
```
