# BUG-008: Credit history uses incompatible transaction vocabularies
> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-08-05 · Project: VideoFly

## Summary

The credit-history route emits lowercase aliases while the UI configuration, TypeScript union, and locale dictionaries use incompatible sets, leaving valid rows without a total presentation mapping.

## Spec reference

- Requirement: REQ-013
- Spec basis: `quality/REQUIREMENTS.md:178-187`
- Behavioral contract quote: "every locale use one credit transaction vocabulary or an explicit total mapping"

## The code

`src/app/api/v1/credit/history/route.ts:21-30` maps database enums to lowercase aliases. `src/components/credits/credit-history.tsx:19-55` keys its display configuration by uppercase database values, while `src/lib/types/dashboard.ts:68-73` and `src/messages/en.json:559-566` define different subsets.

## Observable consequence

When ordinary records such as video consumption, refunds, system adjustments, or payment reversals are returned, the UI can fall back to raw identifiers, wrong icons/colors, or a missing translation key instead of a stable transaction label.

## Depth judgment

Each individual representation looks plausible; the defect appears only when the API value is traced through typing, UI lookup, and every locale.

## The fix

The proposed patch canonicalizes public aliases and aligns the UI/type surface. Its TDD green run exposes one remaining omission: `payment_reversal` is still absent from the locale dictionaries.

```diff
-  VIDEO_CONSUME: "video_generate",
-  REFUND: "video_refund",
+  VIDEO_CONSUME: "video_consume",
+  REFUND: "refund",
@@
-  SYSTEM_ADJUST: "admin_adjust",
+  SYSTEM_ADJUST: "system_adjust",
@@
-  NEW_USER: {
+  new_user: {
@@
+  payment_reversal: {
+    icon: RotateCcw,
+    label: "Payment reversal",
+    color: "text-rose-500",
+  },
```
